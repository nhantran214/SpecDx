# SpecDx P4a — v4 model, execution witnesses, and S3 offline validation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build SpecDx v4 and validate it offline on SOPBench's published runs, on CPU only.

**Scope.** P4a covers:
- the shared-error reading model, with per-cell difficulty, profile likelihood, and the undetermined outcome;
- the S3 execution witness;
- the theory note;
- G0v4, simulated on S3's development domains;
- a placebo control, ablations and a v4 replication on the held-out domains.

Each of these produces a Markdown report through `run_all.sh`.

**Architecture.**
- v4 lives in new modules beside v3 (`specdx/infer/anchored_v4.py`, `specdx/infer/typing_v4.py`). v3 stays unchanged and importable as an ablation.
- The witness replays a task on SOPBench's own strict system (`vendor/sopbench/env`).
- The simulator gains arms and an S3 calibrator.
- New P4a stages extend the existing stage table and CLI.

**Tech Stack:** Python 3.13 (`.venv`), numpy, the vendored SOPBench `env` (stdlib-only modules), pytest, ruff, bash.

**Spec:** `docs/superpowers/specs/2026-11-20-specdx-v4-shared-error-design.md` (v4 design, binding), with `docs/superpowers/specs/2026-10-14-specdx-v3-design.md` §3–§5 for everything v4 keeps.

### v4 model (design §3)
- p_{m,c} = σ(α_m − β_c), with β_c ~ N(β_{g(c)}, cell_sd²) and β_g ~ N(0, beta_sd²).
- **Error distribution when A ≠ ∅.** On V ∖ A it is (1 − λ)·u + λ·δ_e, where e ∈ V ∖ A ∖ {OTHER} and λ ~ Beta(lambda_a, lambda_b).
- **Error distribution when A = ∅.** It is v3's flat-pool ε ~ Dirichlet(κ·u), with κ = 10 and no attractor.
- **Composite weights.** A reading's act group is its `(run_key, scenario)`. A group of size k gets weight 1/k, and only in the α and β_g updates.
- **Per-cell posterior.** It uses the profile likelihood for each candidate set. Each cell's own readings are unweighted.

### Typing (design §5)
- Undetermined: |log profile-LR(best defect form vs best no-defect explanation)| < tau_u (nats).
- Shared error: the MAP set is {d} and λ ≥ tau_lambda.
- Undetermined and shared_error are not defect types.

### S3 split
- Domains are split by a seeded draw, seed `20261120`: 3 development domains and 4 held-out domains.
- The split is committed to `experiments/p4-s3-split.json`.
- G0v4 calibrates only on the development domains. The placebo and the v4 replication run only on the held-out domains.

### Reports
- One Markdown report per stage, in `$P3_RESULTS` (default `results/p3`), with the dashboard in `STATUS.md`.
- Exit codes are 0, 1, 2, 3 and 4, as in P3a.

## Review Focus

1. **A cell whose readings are unanimous.** No ability gradient is possible, so v4 must report it undetermined (or route it to a witness). It must never type it as hidden from the prior alone. Tested in Tasks 2 and 3.
2. **A witness on a task whose strict replay raises.** Expected: outcome "error". The cell stays undetermined and is counted; the domain does not crash. Tested in Task 6.
3. **The login side effect.** A failed login still marks the user as logged in on the strict system. A witness must not call the target after a refused prerequisite. Tested in Task 6.
4. **Placebo on a task where every rater gives the same act vector.** Permutation changes nothing. Such cells are excluded from the placebo ratio's denominator, not counted as survivors. Tested in Task 8.
5. **v4 and v3 reading the same data.** v3's outputs must be bit-identical to before P4a. Tested in Task 1, with a regression test on a fixed fixture.

### Task 1: The v4 per-cell profile likelihood

**Files:**
- Create: `specdx/infer/anchored_v4.py` (first half)
- Test: `tests/infer/test_anchored_v4.py`

**Interfaces:**
- Consumes the following from `specdx/infer/anchored.py`, without changing them: `candidate_values`, `set_log_prior`, `OTHER`, `K_MAX`, `KAPPA`, `SETS`, `CellPosterior`. Also `Cell` and `Reading` from `specdx/infer/cells.py`.
- Produces:
  - `V4Params`, a frozen dataclass with these fields and defaults:
    `pi=0.2, s_mis=0.4, s_amb=0.3, s_empty=0.3, beta_sd=1.0, cell_sd=1.0, mu_alpha=1.0, sigma_alpha=1.0, lambda_a=1.0, lambda_b=3.0, tau_h=0.5, tau_a=0.3, tau_w=0.9, tau_u=2.0, tau_lambda=0.5`.
  - `SetFit(loglik: float, beta: float, lam: float, attractor: str | None)`, frozen. It is the profiled log posterior of one candidate set:
    - the data log-likelihood;
    - plus the log prior of β_c under N(β_g, cell_sd²);
    - plus, for non-empty sets, the log prior of λ;
    - plus, for ∅, the log Dirichlet prior of its MAP ε.
  - `CellPosteriorV4(CellPosterior)`, frozen. It adds the fields `lam: float`, `attractor: str | None` and `log_lr: float`.
    - `beta`, `lam` and `attractor` come from the MAP set's `SetFit`.
    - `log_lr` = (the best profiled log posterior, prior over A included, among the defect forms) − (the best among the no-defect forms). On an anchored cell the no-defect form is {d}. On an unanchored cell it is any single value.
  - `profile_cell(cell: Cell, values: tuple[str, ...], counts: Mapping[str, Mapping[str, int]], alpha: Mapping[str, float], beta_g: float, params: V4Params) -> CellPosteriorV4`.
    - `counts[model][value]` holds the cell's readings, unweighted. Values outside `values` go to `OTHER`.
    - For each candidate set A, maximise over β_c, and over λ and e for A ≠ ∅, or over ε for ∅. Then combine with `set_log_prior` into the posterior over A.

### Task 2: The v4 outer fit

**Files:**
- Modify: `specdx/infer/anchored_v4.py` (second half)
- Test: `tests/infer/test_anchored_v4.py` (add tests)

**Interfaces:**
- Consumes: Task 1.
- Produces:
  - `AnchoredFitV4`, a dataclass with fields `alpha`, `theta`, `family_effect`, `cells: dict[str, CellPosteriorV4]`, `weights`, `converged`, `iterations`, `params: V4Params`, `start`, `starts`.
    - These are the same names and meanings as v3's `AnchoredFit`, so `diagnose`-style callers and `fit.weights` consumers keep working.
  - `fit_v4(cells: Mapping[str, Cell], readings: Sequence[Reading], *, models: Mapping[str, str], params: V4Params, tol: float = 1e-6, max_iter: int = 200) -> AnchoredFitV4`.

**Algorithm.** v3's multi-start EM, from the T3 median start and from common α ∈ {0, 1, 2, 3}. Keep the start with the best total log posterior. Each iteration does three things:
1. **Per cell:** `profile_cell` at the current α and β_g gives post(A), and the faithful probability r of each reading under the profiled parameters.
2. **α and β_g:** penalised logistic Newton steps on the faithful probabilities. Each reading is weighted by 1/k for its act group (`(reading.run_key, reading.scenario)`), with β_c as the offset per cell: each cell's logit uses β_c, and β_g is updated as the mean of its cells' β_c shrunk under its prior.
3. **Convergence:** the largest change in α and β_g is below tol.

`weights[run_key]` is the mean r over the run's readings, as in v3.

The order of `fit.theta` matches α. In the same setting, v3's `fit_anchored` mis-orders or compresses θ; record v3's θ in the report, without asserting it.
  - `test_composite_weights_do_not_change_single_cell_groups`: when every act group has size 1, the result equals the unweighted fit.
  - `test_composite_weights_damp_correlated_groups`: duplicating every reading into k = 4 identical cells of one act group leaves α within 1e-3 of the single-cell fit.
  - `test_fit_reports_convergence_and_start`.

### Task 6: The S3 execution witness

**Files:**
- Create: `specdx/subjects/sopbench/witness.py`
- Test: `tests/subjects/test_sopbench_witness.py`

**Interfaces:**
- Consumes: `SOPBENCH_DIR` and `DOMAINS`.
- Produces:
  - `load_raw_tasks(domain: str, root: Path = SOPBENCH_DIR) -> list[dict]`. It returns the tasks in the same order as `load_tasks`, with `task["user_goal"]` set from the group key.
  - `WitnessResult(outcome: str, calls: tuple[str, ...], error: str = "")`, a frozen dataclass. `outcome` is one of `"succeeds"`, `"refused"` or `"error"`.
  - `witness(domain: str, task: dict) -> WitnessResult`.

**Algorithm** (fixed; from the research run in the controller's notes):
1. Put `SOPBENCH_DIR` on `sys.path` without importing `env.generation`. Then:
   - `dep_innate = domain_assistant_keys[domain].action_innate_dependencies`;
   - `dep_full = get_default_dep_full(domain, "full")`, then set `dep_full[task["user_goal"]] = task["constraints"]`;
   - `strict = domain_keys[domain + "_strict"](deepcopy(task["initial_database"]), dep_innate, dep_full, task["constraint_parameters"])`.
2. `L` is the set of actions in the values of `domain_assistant_keys[domain].constraint_links`.
3. Walk `directed_action_graph` from node 0's children, with `sat(i)`:
   - **"and":** evaluate every child. If any fails, do one more pass over the children; the node is satisfied only if all children pass in that pass.
   - **"or":** the first child that passes satisfies the node.
   - **A leaf not in `L`:** satisfied, and not called.
   - **A leaf in `L`:**
     1. Satisfy its children first.
     2. Then call the leaf with `kwargs = {p: user_known[k] …}`. A missing key fails the leaf.
     3. Then normalise: `ok(r) = r if bool else r[0] if tuple/list else bool(r)`.
4. If a prerequisite fails, the outcome is `"refused"` and the target is **not** called (Review Focus 3). Otherwise call the target with its kwargs and take `ok`.
5. Any exception gives `WitnessResult("error", calls, repr(exc))` (Review Focus 2).
6. Never convert or repair the task data. The bank `credit_cards` list is replayed as is, because it is the defect being witnessed.

### Task 8: The placebo control

**Files:**
- Create: `specdx/subjects/sopbench/placebo.py`
- Test: `tests/subjects/test_sopbench_placebo.py`
